# 초기 설계 결정 — 2026-09-05

## Python 단일 프로세스와 독립 엔진

초기 규칙 검증 비용을 줄이기 위해 게임 엔진은 표준 라이브러리만 사용한다. Gymnasium/PPO는 별도 모듈에서 가져온다. gRPC·C# 이중 환경은 성능 측정으로 필요성이 확인될 때 검토한다. 모델 추론 없이도 엔진 smoke가 실행되어야 한다.

## 버전이 있는 과거 카드 부분 집합

기존 원본 데이터의 패치 식별자는 불명이다. 특정 패치를 임의로 지정하지 않고 SHA가 고정된 4장으로 `archival-subset-v1`을 만든다. 이는 최신 전장 시뮬레이터가 아닌 기본 엔진 검증 단계다. 라이브 패치 지원은 카드 출처·패치 ID·규칙 검증을 갖춘 뒤 별도 버전으로 추가한다.

## 고스트 풀 대신 고정 상대

프로세스 이력에 따라 상대가 변하는 문제를 제거하기 위해 학습과 평가에 별도 고정 템플릿을 쓴다. 과거 모델 상대 학습과 8인 대전은 이 기준 평가가 안정된 뒤 도입한다.

## 작은 MaskablePPO 기준선

기존 PC의 설치된 NumPy/Gymnasium/PyTorch/SB3 버전을 사용하며 직접 의존성 버전을 고정한다. 위치별 카드 ID one-hot과 수치 특징을 사용하는 작은 MLP부터 검증한다. 성능 최적화나 새 신경망은 비교 실험 이후에 도입한다.

## 보수적 모델 호환성과 재개

모델과 함께 코드·규칙·데이터·매핑·런타임 서명을 저장하고 로드 시 일치하지 않으면 실패한다. 현재 재개는 정책·옵티마이저·카운터를 복원하고 새 에피소드에서 시작한다. 중단되지 않은 학습과 같은 RNG 궤적을 재현한다고 주장하지 않는다.

## 운영의 범위

이 PC에서 짧은 테스트·smoke만 실행한다. Grok Bot 계정의 실제 실행 장비·자원·전달 경로는 미확정이다. Bot에 메시지를 보내거나 장시간 학습·예약 루틴을 만들지 않는다. 실행기는 동작 검증 후 해당 Bot에 인계할 준비물이다.
