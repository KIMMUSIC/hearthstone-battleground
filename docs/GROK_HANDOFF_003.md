## 구현과 검증

- `scripts/supervise.py`: Linux 프로세스 그룹 감시, 전체 시간 예산, 샘플링 RSS, TERM/KILL 후 잔여 프로세스 확인, 첫 실패 시 후속 작업 차단, 비정상 종료 전파.
- `scripts/bgai_threaded.py`: 실제 학습·평가 프로세스 안에서 Torch intraop/interop 각각 1로 설정하고 확인 값을 기록.
- `scripts/diagnostic_campaign.py`: 초기 상태·64스텝·128스텝 및 두 기준 정책의 제한된 비교를 순서대로 실행. 학습 실패나 스텝 미달 시 중단.
- `training.py`: 학습 전 checkpoint와 checkpoint 목록 기록. 재개 실행도 시작 상태를 새 run에 보존.
- `evaluation.py`, `cli.py`: `--trace`로 행동 전 관측·골드·보드/손패 수·마스크·선택 행동 및 행동 후 결과를 기록. 기본 평가 정책이나 보상은 변경하지 않았다.
- 대응 테스트를 추가했고 README와 감독기 사용 문서를 갱신했다. 의존성 추가 없음.

Windows Python 3.11.5에서 54개 통과, Linux 전용 6개 건너뜀, Ruff 통과. Linux 6개는 Ubuntu WSL Python 3.12.3에서 실제 프로세스를 생성해 별도로 통과했다. 클라우드 Python 3.11.16에서 전체 60개 통과(6.93초), 감독기 전용 6개도 외부 timeout 아래 별도로 통과(1.66초), Ruff 통과.

독립 코드 검토에서 프로세스 그룹 이탈을 지원하지 않는다는 주석을 명확히 했다. 실제 그룹 이탈, 감독기 SIGKILL, 호스트 종료는 지원하지 않는다. RSS는 20ms 간격 샘플링이며 하드 메모리 상한이 아니다.

## 평가와 행동 원인

모든 정책은 진단용 seeds 201–220, 고정 상대, 최대 8턴·턴당 24행동이다. PPO 학습 seed는 7 하나다. 아래 승률은 게임 승률이 아닌 전투 승률이다.

| 정책 | 평균 보상 | 전투 승률 | 생존율 | 동결 행동 비중 | 강제 턴 종료 합계 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 미학습 PPO | -6.00 | 0% | 0% | 97.19% | 120 |
| PPO 64스텝 | -2.75 | 13.75% | 65% | 74.53% | 90 |
| PPO 128스텝 | -4.10 | 5.30% | 35% | 84.57% | 101 |
| heuristic | 5.30 | 66.88% | 100% | 0% | 0 |
| random | -5.85 | 0% | 0% | 18.54% | 0 |

동결 액션 ID 3의 같은 턴 연속 선택은 미학습 2,659쌍, 64스텝 1,732쌍, 128스텝 2,067쌍이다. 세 모델 모두 최대 24회 연속 동결을 선택했다. 연속 동결 시 관측의 frozen 값이 실제로 번갈아 바뀌는 것도 검증했다. 동결 상태는 관측에 포함돼 있으며 모든 trace 액션이 해당 마스크에서 합법이었다. 이 결과에서 직접 관측된 낭비는 동결/해제 반복이다. 마스크나 관측의 모든 오류가 없다는 일반적인 증명은 아니다.

64스텝은 이 초기화의 미학습 모델보다 좋지만, 128스텝에서는 다시 악화했다. 짧은 학습 한 seed의 기술 통계이며 학습 효과의 일반화·통계적 유의성·실제 전장 실력으로 해석하지 않는다. PPO는 deterministic=True 평가이고 random은 균등 무작위여서 둘의 초기 행동 분포가 같지 않다.

## 다음 실험의 우선순위

보상 패널티나 카드 확대 전에 같은 checkpoint에서 결정적 선택과 확률적 선택을 비교한다. 확률적 평가에는 정책 RNG seed를 별도로 고정·기록하고 초기화·모델·상대는 유지한다. 동결/턴 종료의 확률, 엔트로피, 행동 비중, 강제 종료를 함께 기록해 낮은 학습량에서 argmax가 동결을 반복하는지 분리한다. 이 단계는 아직 구현·실행하지 않았다.

현재 201–220은 이미 결과를 본 진단 세트다. 이후 여러 학습 seed로 성능을 주장할 때는 사전에 고정한 별도 미사용 평가 세트를 사용한다. 장시간 학습과 규칙/보상 수정은 이번 작업에 포함하지 않았다.

이 문서는 스냅샷 작성 이후 추가됐으므로 전달 ZIP에는 포함되지 않는다.
