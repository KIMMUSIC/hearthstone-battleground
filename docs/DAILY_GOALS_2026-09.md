## 공통 실행 계약

1. 프로젝트 `AGENTS.md`, 해당 날짜의 선행 결과, 현재 소스·실험 상태를 읽는다. 계획과 실제가 다르면 실제 증거를 우선한다. 선행 목표가 이미 충족됐으면 재실행하지 않는다.
2. 선행 작업의 누락이 작고 해당 목표에 직접 필요하면 보완한다. 하루 목표 전체를 대체할 만큼 크면 선행 목표를 먼저 마무리하고 현재 목표는 미완료로 남긴다. 다음 날짜 범위를 조용히 끌어오지 않는다.
3. 구현은 최소 변경으로 수행하고 해당 동작의 회귀 테스트, 적용 가능한 lint·통합 검사를 실행한다. 문서만 바꾼 날에는 링크·명세 일관성 검증으로 충분하다. 독립적인 조사·구현·검토는 도움이 될 때만 서브에이전트로 나눈다.
4. 로컬에서는 개발·테스트·결과 분석·실험 실행을 한다. 실제 학습은 로컬 WSL Ubuntu의 확인된 전용 Python 3.11 venv와 Linux 감독기에서 수행한다. 실행·자원 감시·결과 감사까지 필요한 날은 준비만으로 완료 처리하지 않는다.
5. 새 실험은 고유 run ID, 고정 소스·설정·모델 해시, 실제 실행 명령, 종료 조건, 반환 파일을 명세한다. 기존 소스 실행본과 결과를 보존한다. 실행 중인 동일 작업이 있으면 새로 시작하지 않는다.
6. 날짜별 스텝 수는 실험 설계 목표다. 실행 전 측정 속도와 기존 자원 한도로 시간·RSS 감시·디스크 예산을 산정한다. 계획은 사용 가능한 자원이나 새 비용을 보장하지 않는다. 장시간 실행 한도가 없으면 한도가 확인된 짧은 실행과 준비를 끝내고, 필요한 한도를 구체적으로 요청한다. 답이 없다는 이유로 증액하지 않는다.
7. 결과는 평균뿐 아니라 seed별 성능과 실패 행동을 본다. 불확실성 계산에서 동일 모델의 에피소드를 독립 학습 반복으로 취급하지 않는다. 성능 향상이 없더라도 정확한 비교와 결론을 얻으면 실험 목표는 완료할 수 있다.
8. UI 장애와 실험 실패를 구분한다. 정상적인 UI 재관찰은 계속하되, 실패한 실험은 원인을 진단하고 새 실행본·run ID로 수정한다. 같은 실패를 원인 변경 없이 반복하거나 원본 로그를 지우지 않는다.
9. 매 작업 단위가 끝날 때 결과 문서에 상태, 변경 파일, 실행 명령·종료 코드, 결과 파일·해시, 해석, 미완료 항목, 다음 재개 지점을 갱신한다. 로컬 실행은 WSL 배포판·venv·run ID·감독기 로그·마지막 상태를 기록한다. 과거 원격 실행 기록은 이력으로만 연결한다. 비밀 값은 기록하지 않는다.
10. 완료는 날짜별 종료 기준과 증거로 판정한다. 예산 부족·외부 장애는 완료가 아니다. goal 도구의 상태 변경 규칙을 따르며, 이 문서가 별도 goal을 만들거나 재시도 제한을 바꾸지 않는다.

## 결과에 따라 계획을 갱신하는 절차

이하 날짜별 계획은 최초 실행안이다. 실제 결과에 따라 지속적으로 갱신하며, 날짜가 정해져 있다는 이유로 필요 없어진 작업을 수행하지 않는다.

1. **시작 전:** 직전 일일 결과, 코드 변경, 테스트 출력, 해당 실험의 원본·감사 결과를 확인한다. 누락된 증거는 '미확인'으로 표시하고, 확인되지 않은 성공을 다음 단계의 전제로 삼지 않는다.
2. **재계획:** 영향을 받는 현재·후속 날짜의 선행 조건, 작업, 실험 규모, 검증, 산출물, 종료 기준을 수정한다. 실패한 선행 작업은 먼저 해결하도록 재배치하고 완료된 작업은 중복하지 않는다. 일정의 큰 단계가 바뀌면 전체 일정 개요도 수정한다.
3. **작업 중:** 중요한 새 결과가 다음 행동을 바꾸면 해당 의존 작업을 시작하기 전에 계획을 갱신한다. 단순 진행 상황만 바뀌었다면 결과 문서에 기록한다.
4. **종료·인계 전:** 후속 목표가 최신 결과에 맞는지 다시 확인한다. 변경이 없을 때도 결과 문서에 근거와 함께 '계획 유지'를 남긴다. 다음 goal에서 바로 수행할 행동과 남은 장애물을 구체적으로 적는다.

예: 학습 효과가 없으면 자동으로 100만 스텝으로 넘어가지 않고 원인 진단을 먼저 배치한다. 전투 규칙 오류가 발견되면 카드 확대나 학습보다 회귀 수정이 앞선다. 목표가 이미 충족됐다면 해당 작업은 완료 근거를 연결하고 중복 실행하지 않는다. 처리량이 예상보다 낮으면 실제 자원 한도 안에서 실험 규모·순서를 조정한다.

완료된 목표의 당시 계획·결과·판정 기준은 일일 결과 문서에 보존한다. 기존 실험의 성공 기준을 소급 완화하지 않는다. 새 기준은 적용할 새 실행과 함께 명시한다. 원래 목표를 달성하지 못했다면 범위를 줄였다는 이유만으로 완료 처리하지 않는다.

계획 수정은 현재 맡긴 goal의 후속 준비까지 포함한다. 수정한 다음 날짜 목표를 자동 실행하거나 사용자의 자원·비용 한도를 늘리는 근거로 사용하지 않는다.
