# death-summon-research-v1 — 9/13–15 실행 계약

특정 라이브 패치 재현이 아닌 명시적인 연구용 전투 부분 규격이다. 009 고정 실행본과 모델은 변경하지 않는다. 9/11–12 분석 완료 후 적용한다.

## 선택한 효과와 출처

[Blizzard 공식 카드 API](https://hearthstone.blizzard.com/en-us/api/cards?ids=61061,62213,62262,96763,96764)에서 일반 허수아비골렘96763(BG_EX1_556)의 2/3 능력치와 죽메로 손상된 골렘96764(BG_EX1_556t) 2/1을 소환하는 효과를 확인했다(2026-09-06). 원본 cards_raw.json과 일치한다. 원본 SHA256은 기존 RULES.md의 카드 출처를 따른다.

첫 구현은 **일반 골렘의 단순 소환**만 대상으로 한다. 황금 골렘57401/57408은 로컬 원본 근거만 있고 이번 공식 API에서는 확인되지 않아 보류한다. 뱃사람61061의 즉시공격은 별도 순서 규격이 필요해 보류한다. 종족 시너지·죽메 배수·환생·전투의 함성은 포함하지 않는다.

9/15까지는 전투용 명시적 테스트 카탈로그로 검증했다. 9/16에는 일반 골렘을 기본 상점 풀에, 토큰을 소환 전용 데이터에 등록한다. 골렘과 토큰은 황금·자동 트리플 대상에서 제외한다. 데이터·매핑·관측 버전 변경은 [기본 규칙 계약](RULES.md)을 따른다. 미지원 효과는 오류로 거절하며 일반 버프로 대체하지 않는다.

## 연구용 순서 결정

다음 순서는 공식 라이브 내부 규칙으로 확인된 사실이 아니라 이 부분 규격의 결정이다.

1. 공격과 반격의 피해를 함께 적용한다. 양쪽 사망을 수집한 뒤 죽은 기물을 제거한다.
2. 해당 공격의 공격자 측부터, 각 측의 기존 왼쪽 위치 순으로 사망 효과를 처리한다. 효과는 사망 기물당 한 번만 발생한다.
3. 토큰을 사망 위치에 삽입한다. 양쪽 사망 제거로 생긴 공간을 먼저 반영하고 보드 최대7칸을 유지한다. 초과 소환은 생략 수를 기록한다.
4. 일반 교대 공격 순서는 기존 생존 기물을 건너뛰지 않는다. 이미 공격한 위치에 생긴 토큰은 다음 생존 공격자의 차례를 빼앗지 않는다. 아직 차례가 오지 않은 위치의 새 토큰은 그 위치 순서에 참여한다. 방어 중 사망한 다음 공격자의 위치가 대체되면 토큰이 그 차례를 받는다.
5. 소환으로 새로 생긴 기물은 새 entity ID를 갖는다. 다음 일반 공격에서 토큰이 죽으면 그 사망도 동일하게 처리한다. 소환 자체는 즉시공격을 일으키지 않는다.
6. 사망·소환 처리를 마친 뒤 양쪽 잔존 여부를 판정한다. 입력 불변·명시적 RNG·10,000공격 상한을 유지하며 한도를 결과 reason으로 보고한다.

## 검증 기준

- 동시 골렘 사망 후 양쪽 토큰 생성과 제거→소환 순서 trace.
- 공격자/방어자 사망, 중간 슬롯 소환 위치, 다음 생존 공격자 순서.
- 보드7칸 제한 및 초과 소환 기록(합성 테스트), 새 entity ID 충돌 방지.
- 소환 토큰의 후속 사망, 일반/황금 미지원 구분, 잘못된 효과·토큰 거절.
- 같은 seed 재현·입력 불변·빈 보드·도발·보호막·0공격·공격 상한 회귀.
- 기존 효과 없는 전투 결과/공격 trace와 고정 게임 회귀를 유지한다.

새 범용 이벤트 프레임워크나 학습을 추가하지 않는다. 지원 범위를 넓히면 별도 계약/테스트를 먼저 작성한다.
