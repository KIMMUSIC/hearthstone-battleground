# Grok Bot 첫 인계 기록

2026-09-05. Windows 앱 UI를 통해 전용 `BG Training Operator`를 생성하고 역할 및 실행 명세를 전달했다.

## 환경 조사

아래는 Bot 채팅의 보고값이며 Codex가 원본 측정 파일을 검증하기 전이다.

- 클라우드 Debian 13, x86_64, CPU 8코어.
- RAM 총 약 15GiB, 당시 available 약 4.6GiB, swap 없음.
- 디스크 여유 약 110GB.
- Python 3.13.5, numpy 2.2.4, 학습 패키지 미설치.
- Bot은 GPU가 없다고 보고했으나 nvidia-smi 불가만으로 모든 GPU 부재를 증명하지는 않는다. 이번 실행은 CPU로 제한한다.
- 로컬 장비 연결 및 CopyToBox/CopyFromBox 도구가 있다고 보고했다. Windows 명령은 실행하지 않도록 지시했다.
- 경로 존재만으로 재시작 후 지속성을 보장할 수 없다. 보존 보장과 장시간 작업 한도는 미검증이다.

## 요청한 검증

1. 지정 ZIP 하나를 CopyToBox로 전용 클라우드 폴더로 전달하고 해시를 검증한다.
2. 격리 Python 3.11 환경에 프로젝트가 고정한 rl/dev 버전을 준비한다. Torch는 공식 CPU wheel을 사용한다. Windows lock을 Linux에 그대로 설치하지 않는다.
3. doctor, smoke, pytest, Ruff가 모두 통과한 뒤에만 학습한다.
4. 기존 smoke 설정으로 64스텝 학습, 별도 프로세스 모델 평가, 64스텝 추가 재개를 실행한다. 누적 128스텝을 확인한다.
5. 기본 seeds 101–105로 random/heuristic도 평가한다.
6. 원본 로그·환경·freeze·checkpoint·평가를 결과 ZIP으로 묶어 해시와 함께 반환한다.

준비 예산 10분, 추가 디스크 3GiB, 학습 CPU 1스레드, 학습별 외부 timeout 90초 및 내부 협력적 제한 60초, 학습 프로세스 RSS 상한 2GiB를 지시했다. 소스 수정, 추가 학습, 루틴·서비스·과금 자원 생성은 범위에 없다. 한도 적용 여부는 결과에서 검증한다.

반환 대상은 `../handoff/snapshot-001/grok-results-001.zip`이다. 기존 파일은 덮어쓰지 않도록 지시했다.

## 상태

클라우드 검증 요청은 전송됐지만 파일 전달 단계에서 중단됐다. Bot은 `/workspace/hsai-rebuild/snapshot-001` 생성 성공 후 CopyToBox에서 다음 오류를 보고했다.

이는 Grok Bot 로컬 접근 정책의 거부이며 Codex 자동 승인 검토의 거부가 아니다. 접근 설정을 변경하거나 경로를 옮겨 우회하지 않았다.

### 14:46 첨부 전달 성공

사용자의 직접 첨부 요청에 따라 Codex가 Windows 앱의 공식 파일 첨부 기능으로 ZIP을 전송했다. 사용자 수동 첨부가 필수라는 앞선 안내는 잘못된 판단이었다. CopyToBox의 접근 범위와 앱의 파일 첨부 기능은 구분해야 한다.

Bot은 14:46:46에 클라우드 파일 크기 49,542 bytes와 위 SHA256 일치를 보고했다. 같은 예산과 검증 명세를 재개했으며 Python 3.11 환경 준비 중이라고 응답했다. 학습 완료는 아직 확인하지 않았다. 결과 반환은 CopyFromBox 재시도 대신 해당 대화에 결과 ZIP과 SHA256을 첨부하도록 변경했다.

### 운영 스크립트 검토: 확대 실행 불가

반환된 `run_evals_monitored.sh`는 실행하지 않고 텍스트로 검토했다.

1. `torch.set_num_threads`와 `set_num_interop_threads`를 별도 Python 프로세스에 적용했다. 실제 평가 프로세스에 API 설정이 전달되지 않는다. OMP 환경 변수는 있지만 실제 평가의 interop 스레드 수는 미검증이다.
2. 제한 초과 시 백그라운드 셸 PID에만 TERM/KILL을 보낸다. 자식 평가 프로세스가 남을 수 있다. RSS 합산도 직접 자식까지만 포함한다.
3. RSS 초과 반환 코드 4와 일부 일반 오류가 캠페인 중단으로 연결되지 않으며, 최종 `exit 0`이 실패를 가릴 수 있다. 실제 첫 실패 시 네 평가가 모두 rc=1인데도 마지막까지 진행한 기록이 있다.

현재 평가 데이터의 정합성은 통과했지만 자원 제한 집행은 통과하지 않았다. 다음 작업은 Codex 소유 실행 감독기의 실패·자식 종료 회귀 테스트와 구현이다. 세부 순서는 `../experiments/NEXT_RUN_003.md`를 따른다. 기존 checkpoint와 스냅샷은 보존한다.
