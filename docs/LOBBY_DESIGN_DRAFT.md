# 제한된 8인 경기 — 후속 설계 준비

상태: 9/27–28의 사전 조사 메모. 9/21–26 결과와 엔진 검증을 확인하기 전 구현 완료나 해당 날짜 완료를 뜻하지 않는다.

## 공식 근거와 미확인 영역

[Blizzard 전장 소개](https://hearthstone.blizzard.com/en-us/news/23156373/introducing-hearthstone-battlegrounds)는 8인, 모집/전투 반복, 구매3·판매1·리롤1·동결, 트리플과 발견, 전투 전 상대 배치 비공개를 뒷받침한다. [21.2 패치](https://hearthstone.blizzard.com/en-us/news/23712592/21-2-patch-notes)는 짝수 생존자에서 켈투자드를 만나던 오류 수정과 피해 상한 이력을 담는다. [23.6 패치](https://hearthstone.blizzard.com/en-us/news/23817873)는 1티어 복사본을16에서15로 변경했다. [25.2 패치](https://hearthstone.blizzard.com/en-us/news/23892225/25-2-patch-notes)는 피해 상한 조건을 다시 변경했다.

공식 자료만으로 정확한 동시 탈락 순위, 매칭 재대결 창, 유령 선택, 모든 티어 재고·발견·황금 반환량을 확정하지 못했다. 아래는 라이브 패치 재현을 주장하지 않는 프로젝트 규칙 제안이다. 기존 v4 모델·단일 플레이어 규칙은 고정 실행본으로 보존한다.

## 구현 시 확정할 계약

- 8인, 영웅/방어도/주문/종족·패치 확장 없음. 현재 지원7종과 전투 소환 토큰1종 사용. 모집 경제는 기존 v4와 일치시키되 무한 복원 추출은 유한 공유 풀로 교체한다.
- 모집은 라운드별 시작 좌석을 순환하는 순차 처리다. 정책은 자기 상태·합법 행동과 공개 HP/티어/생존 상태의 복사본만 받는다. 다른 손패·상점·발견·현재 보드·재고는 보이지 않는다. 전투 시 보드 스냅샷을 공개한다.
- 살아 있는 플레이어만 한 번씩 전투한다. 홀수이면 한 명이 이전 라운드 사망자의 보드 스냅샷과 전투한다. 유령에 별도 경제·카드 소유권은 없다. 짝수에는 유령을 배정하지 않는다.
- 매칭은 가능한 완전 매칭을 열거해 최근2라운드 상대 반복을 최소화한다. 제약이 불가능하면 최소 위반을 기록하며 진행한다. 무조건 불가능한 '반복 금지'로 멈추지 않는다. 매칭·전투·각 좌석 모집 RNG는 분리한다.
- 전투는 기존 simulate를 재사용하고 실제 모집 보드는 보존한다. 피해는 기존 연구식(승자 티어+생존 기물 티어 합), 라이브 피해 상한 없음.
- 전투 결과를 모두 수집한 다음 동시 HP 갱신·탈락을 처리한다. 같은 라운드 탈락자는 차지한 순위 구간의 평균 순위를 공유한다. 마지막 생존자는1위다. 라운드 제한 도달은 truncated이며 생존자에게 허위 최종 순위를 부여하지 않는다.
- 공유 재고는 상점 지원 카드만 가진다. 1티어15장은 공식 과거 사례, 2티어 수량은 연구용 고정값으로 별도 명세한다. 토큰은0장이고 전투 중 생성·제거가 재고를 바꾸지 않는다.
- 상점 예약은 재고→상점 이동, 구매는 상점→손패, 플레이는 손패→보드다. 리롤/비동결 교체/탈락은 예약을 반환한다. 판매/탈락 시 일반은1장, 황금은기초3장을 반환한다. 트리플은기초3장 보존이다.
- 발견 후보도 재고에서 예약하고 선택1장을 소유권으로 옮기며 나머지는 반환한다. 고갈 시 후보 수를 줄인다. 후보0은 '재고 고갈로 발견 불가' 이벤트로 기록하고 모달에 갇히지 않는다. 실제 라이브 발견 규칙이라는 주장은 하지 않는다.
- 불법 행동은 골드·소유권·풀을 바꾸기 전에 거절한다. 모든 전이에서 초기 재고 = 남은 재고 + 상점/발견 예약 + 손패/보드 기초 복사본을 검사한다. 사망자는 추가 행동을 하지 못한다.

## 검증 설계

경계 사례: 재고0·1·2장, 여러 좌석 동일 카드 요구, 동결/리롤, 황금3장 반환, 발견 미선택 반환, 손패/보드 만석, 죽메 토큰 불변, 홀수/짝수 생존자와 유령, 연속 상대 회피 불가능한2인, 동시 탈락, 종료 후 액션, 라운드 제한 중단.

전체 경기 검증: 여러 seed의 규칙 기반8인 완주, 각 행동 합법·관측 공간 포함, 매 전이 보존량, 같은 seed 전체 trace 재현, 두 로비 교차 실행의 RNG 독립, 정책에 상대 손패·상점·재고 누수 없음. 10/2의 PPO 학습 어댑터는 이 범위에 포함하지 않는다.

## 사전 설계 검토에서 보완한 결정

이 결정도9/26 선행 결과 확인 전까지 준비안이다. 별도 `LobbyGame`, `PlayerState`, `SharedPool`을 사용하고 기존 `Game.step`의 고정 상대·종료 흐름을 상속하지 않는다. `Catalog`, `Minion`, 액션decode와 전투simulate를 재사용한다. 경제 처리 일부가 명시적으로 중복되더라도 v4 실험의 동작을 변경하지 않는다.

- 재고는 지원 카드마다15장(1·2티어 모두)으로 고정한다. 2티어15장은 실제 수량 확인 주장이 아닌 연구용 설정이다. 테스트는 더 작은 수량을 주입해 고갈을 검증한다.
- `SharedPool`은 초기수량/가용수량만 소유한다. 좌석별 `PlayerState.shop`, `pending_discover`가 예약의 실제 장부이고 `hand/board`가 소유의 실제 장부다. 별도 중복 카운터를 소유권 원본으로 두지 않는다. 불변식은 이 실제 컬렉션에서 매번 재계산하며 persistent entity ID 중복도 금지한다.
- 모든 영구 minion은 로비 전체 단조 entity ID를 사용한다. 전투 토큰 ID는 `(round, pairing, transient entity_id)` 범위로 해석하고 영구 장부에 삽입하지 않는다.
- 정책 입력은 새 immutable `PolicyView`다. own 상태의 frozen minion tuple, 합법 액션tuple, 공개로비tuple만 전달한다. 카탈로그는 읽기전용 정의이고 실제Lobby/PlayerState/SharedPool 참조를 제공하지 않는다. 관측 수치공간 검사는 별도 lobby observation helper에서 정의하며 PPO adapter는 만들지 않는다.
- 동점 매칭은 정규화한 페어 목록을 정렬한 뒤 전용matching RNG로 선택한다. 총 최근2라운드 재대결 수를 우선 최소화하고, 홀수 시 유령 연속 배정/누적 배정 횟수를 그 다음 비용으로 최소화한다. 유령은 가장 최근 탈락 라운드에서 최소seat의 전투 직전 보드/티어 스냅샷이다. 이후 새 사망이 생길 때 교체한다. 유령전 피해는 살아 있는 쪽에만 적용한다.
- 라운드 전 생존n, 사후 생존s라면 이번탈락k=n−s명의 평균 순위는 `(s+1+n)/2`다. s=1이면 승자는1위, s=0이면 나머지 모두 해당 평균순위로종료한다. 과거 탈락자의 순위는 변경하지 않는다. 평균순위 전체합36을 확인한다.
- 라운드상한에서 s>1이면 `terminated=False, truncated=True`, 생존자rank=None, eliminated rank만 보존한다. 승자 확정/전원탈락은 `terminated=True, truncated=False`. 종료 이후행동은오류다.
- 발견은 정확한 연구티어에서 가용복사본 가중 추출로 최대3개를 예약한다. 중복후보는 재고가 있을 때만 가능하다. 후보선택 시 선택하지 않은복사본을 반환한다. 후보0이면 명시적 discover_exhausted 이벤트를 내고 정상준비/종료 흐름을 계속한다.

## 구현 전 세부 경계 준비

기본 HP30, 첫 골드3, 다음 라운드 골드 `min(10, round+2)`; 구매3·판매1·리롤1, 판매 후 골드 상한10이다. 티어는1–2, 승급 비용5에서 라운드마다1씩 감소하며 하한0이다. 상점은 티어1에서3칸, 티어2에서4칸이고 행동 인덱스는7칸까지 예약한다. 손패10·보드7·행동24·스왑3 제한과37개 행동을 유지한다. 동결은 토글이며 행동1회를 소비한다. 동결된 상점은 구매 후 빈칸을 포함해 다음 라운드에 그대로 유지하고 자동 보충하지 않는다.

각 모집 라운드의 시작 좌석은 `(round-1) % 8`이며 그 좌석부터 순환해 생존 좌석만 방문한다. 해당 좌석의 라운드 시작 갱신과 예약도 그 순서에 포함한다. 모든 정책은 자기 모집을 끝낸 뒤 다음 정책으로 넘어간다. 전투는 모든 모집 완료 후 시작한다. 한 좌석의 리롤이 다른 좌석의 기존 예약을 가져갈 수 없다.

일반 트리플은 손패와 보드의 같은 일반 카드3장을 소비해 황금1장을 손패에 둔다. 소유 복사본3장을 보존하며 기존 v4의 버프 합산 규칙을 사용한다. 골렘·토큰의 황금/트리플은 비활성이다. 황금 플레이는 정확히 `min(2, tier+1)`티어에서 발견하며 손패 만석으로 선택 불가능한 상태를 만들지 않는다. 마지막 허용 행동에서 발견이 발생하면 선택을 해결한 뒤 준비 완료 처리한다. 발견 중에는 발견 선택만 허용한다.

관측 helper는 정책 view만 인자로 받는다. 자기 정보는 좌석·라운드·HP·골드·티어·승급비용·동결·남은행동·남은스왑을 명시적으로 포함한다. 슬롯 배열은 기존 v4의 카드 인덱스18폭 계약에 따라 상점7·보드7·손패10·발견3개로 패딩하며 황금·공격력·체력·도발·천보를 구분한다. 공개 좌석8개는 좌석순으로 HP·티어·생존·평균순위(미확정0)를 포함한다. HP는 사망 후 음수가 가능하고 버프 수치는 임의로 잘라내지 않는다. numeric space는 이에 맞는 범위를 선언하고 반환값 전체가 공간에 포함되는지 검증한다. 카탈로그 정의와 관측 배열은 내부 엔진 상태를 수정할 수 있는 참조를 담지 않는다.

공개 게임 종료 상태와 순위는 관측 가능하지만 상대 손패·상점·발견·현재 보드·재고는 정책 view와 helper의 입력에 없다. trace는 감사용 완전 기록이며 정책 callable에 전달하지 않는다. 정책 객체가 직접 파일·전역 engine 변수를 읽는 악성 Python 코드를 샌드박싱한다는 주장은 하지 않는다; 검증 대상은 공개 API의 데이터 전달 경계다.
