# 고정 모델의 행동 선택 방식 진단

추가 학습 0스텝. snapshot-003의 미학습/64/128스텝 checkpoint를 그대로 사용한다. `src/`와 규칙은 변경하지 않는다. 별도 `scripts/selection_probe.py`는 기존 로더의 호환성 검사를 그대로 거치며 모델 파일 해시를 이전 평가와 대조한다.

각 모델에서 게임 seeds 201–220을 사용해 argmax 1회와 확률적 선택 3회(정책 seeds 11,22,33)를 비교한다. 총 12조건·240게임이며 240개의 독립 학습 표본을 의미하지 않는다. 같은 초기화 seed 7에서 나온 세 checkpoint다.

확률적 선택은 마스킹된 정책 분포를 `torch.multinomial`과 전용 CPU Generator로 샘플링한다. 정책 seed와 게임 seed의 SHA256에서 에피소드별 seed를 만들고 기록한다. 게임 RNG나 Torch 전역 RNG를 정책 샘플링에 사용하지 않는다. argmax는 기존 결정적 평가와 전체 에피소드 지표가 같아야 통과한다.

각 행동에 37개 확률, 마스크, 선택 행동, frozen 상태, 남은 행동 수, 보상, 강제 종료, 엔트로피(nats), 최고 확률과 1·2위 확률 차이를 저장한다. 동결은 ID3, 턴 종료는 ID0이다. 확률 합·마스크·모델 전후 해시와 원본 평가 회귀를 검증한다.

정책별 방문 상태가 다르므로 평균 엔트로피나 동결 확률을 같은 상태에 대한 직접 비교로 해석하지 않는다. 공통 첫 관측과 실제 선택 비중을 구분해 분석한다. 확률적 선택이 반복을 줄이더라도 승률이나 평균 보상이 좋아지는지는 별도로 판단한다. 이미 결과를 본 seed들을 최종 일반화 평가에 사용하지 않는다.

Grok Linux의 기존 venv311에서 새 테스트2개와 Ruff를 먼저 통과시킨 뒤, snapshot-003의 검증된 감독기로 전체180초·샘플링 RSS2GiB·CPU1스레드·추가디스크100MiB 범위에서 실행한다. 설치·삭제·재학습 없이 새 probe-004 폴더에만 결과를 남긴다. 결과와 원본 로그는 ZIP으로 회수한다.

전달 ZIP SHA256: `1ed2f0039f10786e8eef8360c4bb4cf5d16f7fcc4953df8a6221dedc0bdf2338`, 3745bytes. ZIP에는 평가 스크립트·테스트·개별 해시만 포함되며 이 명세는 별도 기록이다.
