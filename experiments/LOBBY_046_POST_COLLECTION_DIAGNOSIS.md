# 046 — 데이터 출처별 오류 진단 명세

상태: 진단·독립 대조 완료. [10/17 결과](../docs/daily/2026-10-17.md). 아래는 실행 전에 확정한 명세다. 045 독립 감사 passed를 확인했다. 평균순위6.90→7.00위·개선seed1/3·후보2개의dev정확도75%미달로045후보는미채택이다. 045 결과에 근거한 다음 단계이며 새 학습은 포함하지 않는다.

## 목적과 범위

045의 방문 상태 추가가 어떤 데이터에서 도움이 되고 어떤 데이터에서 기존 행동을 해치는지 확인한다. source별 분류와 자기 행동의 경기 성능을 구분한다. 가중치·엔진·예산 변경, 카드 확대, PPO 연결을 하지 않는다. CPU1/1, 기존 모델 읽기 전용, 새 진단 JSON, 입력 파일 덮어쓰기 없음. 예약 holdout을 사용하지 않는다.

입력은 runs/lobby-045-local-r1의 고정 src와 control/candidate 최종 모델(seed7·17·27), outputs/dataset-s007-teacher의 train/dev, seed별 collect-sXXX-candidate의 train/manifest/collection, evaluate-sXXX-control/candidate/final.json이다. checkpoint와 입력 데이터의 해시가045 FILES/반환 ZIP/audit 증거와 맞는지 확인한다. 실행 전후 모든 사용 입력의 해시가 같아야 한다.

## 비교와 분모

같은 seed의 두 모델을 정확히 같은 세 코퍼스에 적용한다. teacher 기본 학습 행은 [0, base_train_rows), collector 추가 행은 [base_train_rows, augmented_train_rows), dev는 별도 바이트 불변 파일이다. 접두부와 manifest/collection 행 범위를 재검증한다. source × arm × seed별 rows, 정답 빈도, micro, 실제 존재 정답 클래스의 macro, NLL, 37×37 혼동 행렬을 기록한다. 기본/추가 코퍼스는 학습 데이터이며 일반화 평가로 표현하지 않는다.

기존에 저장된 최종120경기(6모델×20개 final.json episode)는 새 평가 표본을 생성하지 않고, 저장 상태마다 deterministic prediction을 저장 행동과 대조한 뒤 저장 행동을 실행한다. 매 행동의 관측·합법성·카드 보존, 종국 rank/reward/terminated/truncated와 전체 trace/info를 원본 final.json과 비교한다. 실제 방문 상태의 teacher 일치율을 별도 분모로 집계한다. source 코퍼스와 경기 상태를 섞어 정확도를 계산하지 않는다.

라운드1–3/4–6/7+별 teacher 일치율과 오류만 우선 집계한다. ACTIONS의 고정 kind와 index를 사용한다. kind가 다르면 행동 종류 오류, 같은 kind인데 action ID가 다르면 슬롯 오류다. 현재 registry의37개 항목을 확인하고 구매·배치 등의 슬롯을 임의로 같은 행동으로 합치지 않는다. 첫 불일치와 전체 오류의 종류/슬롯 수를 따로 기록한다. 골드·손패·보드·티어 분포는 이번 필수 산출물에서 제외한다.

## 완료 기준과 후속 분기

모든6모델×3코퍼스 분류와120경기 전행동 재현, 출처 경계·분모·입력 불변 검증이 통과하면 진단 완료다. 경계 테스트는 빈/불일치 범위, 클래스 누락과 macro 분모, 반순위, 슬롯/종류 구분, trace 변조 거부를 포함한다. 전체 숫자를 source별 표로 보고하고045의 기존 candidate_keep 판정을 바꾸지 않는다.

후속 가설의 우선순위는 아래 순서로 정한다. 어느 분기도 인과관계나 성능 채택을 뜻하지 않으며 새로운 학습은 별도 명세가 있어야 한다.

1. 같은 seed에서 후보의 추가 코퍼스 micro가 대조군보다 높고 기본 코퍼스 micro가 낮은 경우가2/3 이상이면 데이터 출처 간 정확도 상충을 우선 검토한다.
2. 위 조건이 아니고 추가 코퍼스 micro가 개선되지 않은 seed가2/3 이상이면 추가 상태 학습 자체의 실패를 우선 검토한다.
3. 그 외에는 후보의 dev 대비 자기 방문 상태 일치율 격차가20%p 이상인 seed가2/3 이상인지 확인해 남은 상태 분포 차이를 검토한다.
4. 해당 조건이 없으면 증거 부족으로 기록하고 자동 튜닝을 시작하지 않는다.

행동 쌍 집중도의 분모는 각 후보의 기존 최종 경기 방문 상태에서 발생한 전체 오류 수다. 정답 일치는 제외하고 같은 종류의 슬롯 오류는 포함한다. 선택된 분기에서 동일한 정답/예측 행동 종류 쌍이 이 오류의50% 이상을 차지하는 seed가2/3 이상이면 그 쌍으로 다음 읽기 전용 분석을 좁힌다. 넓은 하이퍼파라미터 탐색이나 반복 데이터 추가는 계획에 넣지 않는다. 반복 사용한 dev20001..20020을 최종 holdout으로 부르지 않는다.
