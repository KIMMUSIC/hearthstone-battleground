# 확장 환경 10만 스텝 캠페인 — 9/20 사전 설계

상태: 준비 중. 최종 소스·분리 평가 입력 해시와 실측 예산은 9/19 완료 후 확정한다. 실제 학습은 9/21 범위이며 아직 실행하지 않는다.

## 조건과 비교

신규 초기화 seed는 7, 17, 27이다. 확장 카드 풀을 공통으로 사용하고 학습 상대는 fixed-v1을 유지한다. 비교의 주요 변화는 학습량이다. 후보별로 보상·카드·상대 분포를 바꾸지 않는다. 완료된 diverse-v1 기각 결론을 소급 변경하지 않는다.

각 seed당 신규 100,000스텝(32 rollout의 3,125배), 전체 300,000스텝을 계획한다. 초기 0, 중간 49,152, 최종 100,000에서 비교한다. 기존 CPU1·협력적 60초·감독기 180초 한도를 지키기 위해 최대 8,192스텝 단위로 순차 실행한다: 8,192 × 12 + 1,696 = 100,000. 모든 세그먼트는 정책·옵티마이저·누적 카운터를 복구한다. 환경/난수 궤적은 세그먼트 경계에서 재시작되므로 단일 연속 실행과 동일한 궤적을 주장하지 않는다. 세 seed에 동일한 경계를 적용한다.

## 평가 분리와 접근

- 019의 실행 검사용 seed/상대는 개발·최종 평가와 분리한다.
- 개발 평가는 사전 고정된 100개 seed를 모든 후보·기준선에 동일하게 사용한다. 각 모델 시점은 seed별 100게임, 총 900게임이다. 9/20에는 heuristic/random 기준선 각 100게임만 실행한다.
- 최종 평가는 별도 100개 seed와 상대 입력으로 보관한다. 학습·개발 평가 코드의 입력 경로에 포함하지 않는다. 9/20에는 최종 성능을 측정하지 않는다. 개발 판단 후 동결한 후보에만 한 번 사용하며, 결과를 본 후에는 개발 데이터로 분류한다.
- 학습 경로는 평가 파일을 읽지 않는다. 파일 해시와 접근 금지 회귀 테스트를 통해 확인한다.

## 수치 판정 — 결과를 보기 전에 고정

주 지표는 seed별 최종−초기 평균 게임 보상 차이다. 학습 진행 판정은 세 seed 평균 차이 ≥ +0.5이고, 최소 2/3 seed가 양수이며, 평균 생존율 차이가 −0.05 이상인 경우다. 100만 스텝 증액 후보가 되려면 이 조건에 더해 heuristic 대비 평균 보상 차이 ≥ −0.5를 만족해야 한다. 통과가 실제 게임 실력이나 100만 스텝 실행 승인을 뜻하지 않는다.

승/무/패, 전투 승률, 피해량, 생존율, 평균 행동 수, 강제 턴 종료, 리롤·스왑·동결 사용량을 함께 보고한다. 에피소드 수를 독립 학습 seed 수로 오해하지 않는다. 신뢰구간은 기술 통계로 표시하고 n=3 seed의 한계를 명시한다. 평가가 실패하거나 환경 불일치가 있으면 성능 판정을 보류한다.

초기·중간·최종 모델과 결과를 모두 보존한다. 개발 평가를 본 뒤 위 기준을 바꾸거나 유리한 seed만 선택하지 않는다. 결함을 수정하면 새 소스 버전과 새 실험으로 구분한다.

## 자원 상한

각 세그먼트 CPU1, 협력적 학습 60초, 감독기 180초, 표본 RSS2GiB를 유지한다. 세그먼트는 병렬 실행하지 않는다. 출력과 반환 ZIP 합계 1GiB 한도 안에서 진행하고 한도 도달 시 중단·보존한다. 전체 예상 시간과 평가 상한은 019 실측 후 수치로 확정한다.
