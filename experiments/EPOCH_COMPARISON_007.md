# PPO epoch 1 대 4

고정된 8192스텝·학습 seeds7/17/27에서 n_epochs만1→4로 변경한다. 기존006의 epoch1 결과를 기준으로 사용한다. 신규 학습3회, 초기/최종 각각 게임 seeds201–220과 argmax/정책 seeds11/22/33을 적용해 총480게임을 평가한다. 초기화부터 새로 학습하며 기존 checkpoint를 재개하지 않는다.

rollout32/batch32, 학습률, 규칙·보상·상대·관측·카드·스레드·학습 seed를 유지한다. 예상 최종 업데이트 수는1024(기존256)이며 업데이트 수와 학습 시간을 함께 보고해 계산 비용 증가를 숨기지 않는다.

주 판정은 세 seed 평균과 seed별 argmax/확률적 선택의 보상·생존·전투 승률 변화다. 한 seed의 최고 결과만으로 채택하지 않는다. 초기 평가가006과 일치하는지 확인하고, 행동 낭비와 정책 엔트로피도 비교한다. 개선되더라도 새로운 평가 seed·상대에서 검증하기 전에는 최종 성능 개선으로 확정하지 않는다.

기존003 checkout과 Linux venv311을 사용한다. CPU1스레드, 학습별60초, 테스트·Ruff·학습·평가 전체 감독180초, 샘플링 RSS2GiB, 새 출력 디스크100MiB다. epoch1의8192스텝이 약6초였음을 근거로 예산을 잡았지만, 초과 시 중단하고 설정을 임의로 늘리지 않는다.

Grok은 전달된 run_007.py 한 진입 명령만 실행한다. supervisor 디렉터리를 사전 생성하지 않는다. 오류면 로그를 보존하고 중단하며, 폴더 삭제·재시도·설치·소스 수정 없이 증거를 반환한다. 감독 명세에는14테스트와Ruff가 먼저 있고 성공할 때만 학습이 시작된다.
