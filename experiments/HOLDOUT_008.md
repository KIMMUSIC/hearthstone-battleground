# 학습 없는 일반화 검증

평가 전에 두 조건을 고정한다. 게임 seeds301–320은 기존201–220과 겹치지 않는다.

1. fresh-seeds: 기존 평가 상대를 유지하고 게임 seed만 변경한다.
2. shifted: 같은 새 seed에 별도 고정 상대 구성을 적용한다. 턴별 보드 수1/2/2/3/4/5/6/7과 상대 tier1/1/2/2/2/2/2/2는 유지하고 카드 구성·순서를 바꾼다. 새로운 카드나 실제 패치 일반화를 의미하지 않는다.

006 epoch1 및007 epoch4의8192스텝·학습 seeds7/17/27 모델6개를 모두 평가한다. 모델별 argmax20게임, 정책 seeds11/22/33 확률적 선택60게임을 조건별로 수행한다. 각 조건에 휴리스틱·무작위20게임씩을 추가한다. 총1040게임, 추가 학습0스텝이다. 결과를 본 뒤 상대나 seed를 바꾸지 않는다.

주 판정은 각 조건에서 epoch4의 세 학습 seed 평균 보상·생존율이 epoch1보다 개선되는지다. seed별 변화와 전투 승률·동결·강제 종료를 함께 보고한다. 두 조건에서 모두 개선되면 다음 환경 확장의 후보로 유지하되 통계적 유의성·실전 성능을 주장하지 않는다. 한 조건에서만 개선되면 조건 의존으로 분류한다.

실행 전 모델6개 해시를 기존 감사된 ZIP에서 고정한다. 소스·규칙·관측·보상·학습 checkpoint는 바꾸지 않는다. 원본 trace로 합법성·확률·보상 합을 재계산하고 실행 후 모델 해시를 다시 검사한다.

기존 Linux venv311·snapshot003을 사용한다. 테스트7개→Ruff→평가를 검증된 진입기에서 순서대로 실행한다. CPU1스레드, 전체180초, 샘플링 RSS2GiB. 이전480게임 출력이 약35MiB였으므로1040게임 및 포장 여유를 포함해 새 디스크150MiB를 감시한다. 시간·메모리·디스크 초과나 오류 시 중단하고 원본을 반환한다. 설치·삭제·수리·재시도·Windows 명령은 하지 않는다.

전달 ZIP 내부의 jobs.json에 정확한 모델 경로·SHA256·seed·상대 파일을 저장하며 상대 원문도 패키지에 포함한다. Grok은 단일 run_008.py 명령만 실행하고 supervisor/results를 미리 만들지 않는다.
