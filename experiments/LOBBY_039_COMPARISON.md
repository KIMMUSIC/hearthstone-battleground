# 039 — rollout 길이 단일 변수 비교

038에서 실제 rollout32 안의 종국 보상 연결 비율은35.35%, 동일 trajectory를128로 재분할하면79.10%였다. 이는 짧은 학습 구간 가설의 근거이며 성능 증거는 아니다.

두 조건 모두 heuristic3/random4, observation_scale=fixed-v1, gamma1, GAE lambda0.95, batch32, epochs4, 좌석0, 최대100라운드다. 대조군 n_steps32, 후보128만 바꾼다. 037은 성능 미채택 상태를 유지하며 fixed-v1은 초기 포화를 줄이기 위한 공통 실험 기준이다. 보상/카드/상대를 추가 변경하지 않는다.

seed7·17·27, 각 모델8,192스텝, 총49,152스텝. 초기 가중치 쌍 일치. 대조군 SB3 _n_updates=1024, 후보=256이지만 Adam의 실제 파라미터 step 카운터는 양쪽1024여야 한다. _n_updates를 optimizer 호출 수로 오인하지 않는다. rollout 갱신 간격 변화는 이번 단일 변경의 일부다.

공통 heuristic7, 개발 seed20001..20020, 초기/최종 각20회×6모델=240, heuristic/random 각20회=40, 합계280평가 및 최종 첫2seed 재현. 학습 seed0..9999. 기존 예약 최종 seed와22001..22100은 미사용.

채택 기준은 이전과 동일: 평균 대조군−후보 순위≥0.5, 개선 seed≥2/3, 후보 초기→최종 평균개선≥0.5, 상위4위 비율 비감소, 제한중단0. 모든 seed를 보고하고 실패하면 원인 검토로 돌아간다. 통과 기준을 소급 변경하지 않는다.

CPU1·학습당60초·감독180초·샘플링RSS2GiB·출력+반환1GiB. 새로운 고정run에서 수행하고 자동 재시도 없음. 완료 증거는 전체 평가 행동 재현, optimizer 및 SB3 카운터 각각 검증, 초기가중치·파일 해시·자원 감사와 판정 보고다.
