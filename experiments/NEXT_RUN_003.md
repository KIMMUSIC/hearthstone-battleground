# 다음 실행: 운영 감독기 검증 후 학습 효과 분리

2026-09-05 실행 완료: 1단계 감독기 구현·실제 Linux 실패 시험과 2단계 미학습/64/128스텝 행동 추적을 완료했다. 클라우드 60개 테스트 통과, 동결/해제 반복을 확인했다. 결과와 남은 단계는 `../docs/GROK_HANDOFF_003.md`를 따른다. 아래 내용은 실행 전 명세로 보존한다.

## 현재 판정

클라우드 저장·평가·64→128스텝 재개와 결과 회수는 성공했다. 20개 고정 평가 seed에서 128스텝 모델은 64스텝보다 평균 보상이 1.35 낮았다. 학습 효과는 아직 입증되지 않았다. 운영 스크립트의 자식 종료 및 오류 전파 결함을 먼저 해결한다.

## 1. Codex 구현 및 실패 시험

감독기는 `src/` 밖의 운영 코드로 작성해 기존 모델 호환 서명을 유지한다. 새로운 패키지를 추가하지 않는다. Grok Bot은 확정된 파일만 실행한다.

- 실제 평가 Python 프로세스 안에서 Torch intraop/interop 설정과 확인 값을 기록한다.
- 독립 프로세스 그룹을 만들고 시간 초과·RSS 초과·취소 시 그룹 전체를 종료하고 회수한다. 감독 대상이 그룹에서 이탈하는 실행 형태는 지원하지 않는다고 명시한다.
- 후손을 포함한 RSS를 관측한다. 샘플링 감시는 하드 메모리 상한과 구분한다. 엄격한 상한을 주장하려면 실행 환경의 cgroup 지원과 실제 적용을 검증한다.
- 첫 비정상 종료 시 다음 정책을 시작하지 않는다. 캠페인은 비정상 종료 코드와 구조화된 실패 원인을 보존한다.
- 실제 argv, 시작/종료 시각, 제한값, 관측 최대 RSS, 자식 종료 결과, 파일 해시를 남긴다. 출력 경로는 덮어쓰지 않는다.

구현 전 회귀 테스트는 정상 종료, 의도적 exit 7, 자식·손자 프로세스를 동반한 timeout, TERM 무시 후 KILL, RSS 초과, 후속 작업 미실행을 포함한다. Linux용 감독기는 실제 Linux에서 시험한다. Windows의 모킹 테스트만으로 프로세스 종료를 통과 처리하지 않는다.

검증용 더미 작업만 사용하고 학습은 실행하지 않는다. 각 더미 작업 5초, 전체 시험 60초, 메모리 시험은 낮은 테스트 임계치로 수행한다. 기존 가상환경에서 실행하며 추가 설치·삭제는 하지 않는다. 감독기 자체 결함에 대비한 독립된 외부 timeout과 잔여 프로세스 확인을 포함한다.

## 2. 학습 전 진단

운영 시험을 통과한 뒤 새 실행본을 만든다. 필요하다면 초기화 직후의 PPO checkpoint 저장 및 행동 추적 기능을 Codex가 추가한다. 소스가 바뀌면 별도 스냅샷과 해시를 사용하고 기존 checkpoint의 호환성 검사를 우회하지 않는다.

- 동일 학습 seed 7의 미학습 PPO, 64스텝, 128스텝을 비교한다. 서로 다른 소스 서명의 모델을 섞지 않는다.
- 진단용 평가 seeds 201–220, 고정 상대, 8턴/턴당 24행동을 유지한다. 이미 결과를 본 이 seed들은 최종 검증 세트로 쓰지 않는다.
- 총 보상 외에 전투 승률, 생존, 피해, 강제 턴 종료를 비교한다.
- 행동 제한에 자주 도달한 게임의 액션 ID, 마스크, 골드, 보드·손패 수를 기록해 반복 구매·교환·턴 종료 선택을 추적한다. 진단 전에 보상 패널티를 추가하지 않는다.

이 단계의 통과 기준은 데이터·모델 대응과 행동 원인 추적이 가능하다는 것이다. 반드시 성능이 상승해야 한다는 기준은 두지 않는다.

## 3. 이후 성능 실험

여러 학습 seed, 더 긴 학습 예산, 별도 미사용 평가 seed, 불확실성 분석은 위 두 단계 이후에 사전 명세로 확정한다. 현재 문서는 장시간 학습이나 설치 예산 확대의 승인으로 사용하지 않는다. CPU 최종 설치가 작아졌더라도 최초 3GiB 디스크 예산 위반은 이력에 유지한다.
